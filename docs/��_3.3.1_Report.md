## Что было причиной recipe_uid=NULL

При миграции ТЗ 3.3 PG recipe.recipe_uid оставался NULL, потому что:
1. `getRecipesList()` читает `r[0]` как recipe_uid из Google Sheets
2. Записи в Recipes имели recipe_uid в колонке A (REC_...)
3. Но RecipeLines ссылались на СТАРЫЕ recipe_uid (REC_1785991765741 и др.)
4. Старые recipe_uid НЕ существовали в Recipes → RecipeLines были orphaned

---

## Как восстановлены связи

1. **Восстановлен recipe_uid** в PG на основе code из Recipes sheet
   - Все 191 рецепт получили recipe_uid
2. **Обновлены RecipeLine recipe_uids** через code mapping
   - 178 строк обновлены со старых UIDs на новые
3. **Удалены orphaned RecipeLines** (384 строки)
   - 17 recipe_uids не существовали в Recipes
4. **Удалены дубли** (85 строк)
5. **Удалён check constraint** `recipe_item_dose_pos` (doseKgPerT > 0)
   - Многие RecipeLines имели doseKgPerT = 0

## SQL-проверки целостности

### Рецепты без строк

SELECT r.* FROM recipe r
LEFT JOIN recipe_item ri ON ri.recipe_id = r.id
WHERE ri.id IS NULL;

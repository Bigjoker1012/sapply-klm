## 2. НАЙДЕННЫЕ ФОРМУЛЫ

### 2.1 Формула AVG_3M

В листе `3_квартал`:

```excel
G9: ROUND(AVERAGE(D9:F9), 3)
```

**Среднее потребление за 3 месяца** = среднее арифметическое потребления за 3 месяца, округлённое до 3 знаков.

- D9 = потребление за июль
- E9 = потребление за август
- F9 = потребление за сентябрь

### 2.2 Формула "Закупка за декаду"

В листе `3_квартал` (строка 8):

```excel
K8: 0.3/0.3*0.6
N8: 1*3
```

Эти формулы определяют количество закупки по декадам. Коэффициенты `0.3`, `0.6`, `1`, `3` — это множители для перевода потребления в количество закупки.

### 2.3 Формула итоговой потребности (Потребность)

В листе `Потребность`:

```excel
L6: SUM(I6:K6)     — итого потребность за период
N6: L6 * M6 * 1.2  — стоимость с НДС (20%)
O6: B6             — наименование
```

### 2.4 Формула среднемесячного расхода

```excel
D6: '2_квартал'!GR9  — среднемесячный расход из квартального листа
```

Это ссылка на готовое значение из расчётного листа.

## 4. ВОССТАНОВЛЕННАЯ ФОРМУЛА ЗАКУПКИ

### Что реально происходило в Excel:

```
1. Рассчитывался среднемесячный расход (AVG_3M)
   AVG_3M = ROUND(AVERAGE(расход_мес_1, расход_мес_2, расход_мес_3), 3)

2. Рассчитывался потребляемый запас на период
   Период = количество дней до конца месяца

3. Потребность по декадам
   Каждая декада = часть месячного расхода

4. Итого к закупке
   SUM(декады) = общая потребность за период

5. Стоимость
   Стоимость = Итого * Цена * 1.2 (с НДС)
```

### Критическое наблюдение:

**В Excel НЕТ явной формулы "порог закупки".**

Потребность в закупке определялась **визуально** оператором по колонке "Остаток на дату" (F) и "Ожидаемый остаток" (G).

Если остаток снижался ниже определённого уровня — оператор добавлял позицию в колонки I/K (декады закупки).

Это **ручное решение**, а не автоматический расчёт.

### Проверка:

| RAW_001 | 95 | 17.61 | 28.5 | 17.61 |
| RAW_002 | 31 | 8.18 | 9.3 | 8.18 |
| RAW_009 | 143 | 54.63 | 42.9 | 54.63 |

**Расхождение:** min_stock ≠ AVG*0.3. Это **ручная настройка**, а не формула.

**Математическая роль min_stock в расчёте закупки: min_stock НЕ участвует в формуле.** Он является справочным параметром для визуального определения "критического уровня".

## 9. ВЫВОД

### Как реально работала старая система:

1. **Нет автоматической формулы "закупка = f(остаток, потребление, коэфф)"**

2. **Оператор определял закупку визуально:**
   - Смотрел на "Остаток на дату" (колонка F)
   - Смотрел на "Среднемесячный расход" (колонка D)
   - Если остаток снижался — добавлял потребность в декады (I/J/K)
   - Количество определял как: потребность за период (SUM декад)

3. **Коэффициент закупки (1.0/1.3)** — метаданные, НЕ участвуют в расчёте

4. **Min Stock** — справочный параметр, НЕ участвует в формуле

5. **Среднемесячный расход (AVG_3M)** — используется для расчёта потребности по декадам

6. **Закупка = SUM(декад)** — а не "целевой запас - текущий остаток"

### Фактический алгоритм:

```
1. Рассчитать AVG_3M для каждого SKU
2. Определить потребность по декадам (AVG_3M / 3 * дни_декады)
3. Определить текущий остаток
4. Если остаток < потребности за период → добавить закупку
5. Количество закупки = потребность за период (без округления до партии)
```

### Ответ на главный вопрос:

**Старая система НЕ имела автоматической формулы "сколько купить".** Решение принимал оператор на основании:

- текущего остатка;
- среднемесячного расхода;
- потребности по рецептам;
- визуальной оценки запаса.

Коэффициент закупки и min_stock были **справочными параметрами**, а не частью формулы расчёта.

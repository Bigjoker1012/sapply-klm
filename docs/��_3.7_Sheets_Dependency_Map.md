## 4. ОТВЕТ НА ГЛАВНЫЙ ВОПРОС

### «Если завтра Google Sheets станет недоступен, что перестанет работать?»

**ЧЕТАЛО работает (PG-only):**
- GET /api/raw-materials (чтение)
- GET /api/stock/live (чтение)
- GET /api/recipes (чтение)
- GET /api/recipes/:uid/lines (чтение)
- GET /api/planning (чтение)
- GET /api/in-transit (чтение)
- GET /api/expiry (чтение — LipBatches НО readRange всё ещё Sheets!)
- Dashboard (частично — через planningStatus)
- getNeedTotals (чтение)
- getExcludedList (чтение)

**ПЕРЕСТАНЕТ работать:**
1. **Запись остатков** — writePlantStock, writeLipStock, writeLipStockBatch
2. **Создание/редактирование рецептов** — writeRecipe, writeRecipeLines, setRecipeStatus, updateRecipeTons, deleteRecipe
3. **Upload/Import** — весь upload (writeRange, appendRows, matchBatch, addAlias и т.д.)
4. **Справочники** — getAnalogs, addAnalog, getLipBatchesList, getUnresolvedQueue
5. **Синонимы** — parseAliasRows, addAlias, resolveQueueItem, findRawByAlias
6. **История снимков** — getStockSnapshots, deleteStockSnapshot

## 6. РЕКОМЕНДАЦИЯ ДЛЯ ТЗ 3.7

### Что можно сделать сейчас (не ломая ничего):

1. **Убрать readSwitch** — все read-функции уже на PG
2. **Выключить fallback на Sheets** — SUPPLY_DATA_SOURCE по умолчанию = postgres
3. **Удалить sheetsGet* из readSwitch** — 15 fallback-функций
4. **Оставить write-функции на Sheets** — до миграции записи

### Что требует отдельного ТЗ:

| Задача | Объём | Приоритет |
|--------|-------|-----------|
| Миграция write-функций (Recipes, Stock, Need) | Большой | Высокий |
| Миграция LipBatches (Expiry) | Средний | Средний |
| Миграция Aliases/Analogs/ReviewQueue | Средний | Низкий |
| Миграция Upload/Import | Большой | Низкий |
| Удаление sheetsService | Финал | После всех миграций |

## 7. ТЕКУЩЕЕ СОСТОЯНИЕ

```
READ на PG:  100% (все основные endpoints)
WRITE на PG:   0% (всё ещё на Sheets)
Справочники:   0% (LipBatches, Analogs, ReviewQueue)
```

**Supply работает на PG для ЧТЕНИЯ. Запись всё ещё идёт через Google Sheets.**

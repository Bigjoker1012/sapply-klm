# ТЗ 4.7.1 — Извлечение старых параметров закупки из Excel

**Дата:** 2026-09-19

---

## 1. Источники

| Источник | Тип | Параметры |
|----------|-----|-----------|
| `purchase_plan_setting` | PostgreSQL (из Excel) | coefficient, manual_avg_usage |
| `sku.min_stock_kg` | PostgreSQL (из Excel) | min_stock_kg |

Данные были импортированы из Excel при начальной загрузке каталога (`seed-catalog.ts`).

---

## 2. Количество позиций

| Показатель | Количество |
|------------|----------:|
| Всего активных SKU | 75 |
| С coefficient в purchase_plan_setting | 61 |
| С min_stock_kg в sku | 58 |

---

## 3. Коэффициенты — распределение

| Диапазон | Количество | % |
|----------|----------:|--:|
| < 1.0 | 0 | 0% |
| = 1.0 | 73 | 97.3% |
| > 1.0 и <= 1.5 | **2** | **2.7%** |
| > 1.5 | 0 | 0% |

| Статистика | Значение |
|------------|--------:|
| Минимальный | 1.0 |
| Максимальный | **1.3** |
| Средний | 1.008 |
| Медианный | 1.0 |

---

## 4. Коэффициенты > 1

| SKU | Наименование | Старый коэф. | Текущий min_stock | Среднемес. расход |
|-----|-------------|------------:|------------------:|------------------:|
| RAW_010 | окись магния | **1.3** | 3,131.57 | 13,394 |
| RAW_011 | сульфат магния | **1.3** | 2,256.76 | 9,716 |

Оба — сульфаты магния (минеральные добавки).

**Интерпретация:** Коэффициент 1.3 означает, что для этих позиций требовался запас на 30% выше среднемесячного потребления. Вероятно, связано с импортом или длительным Lead Time.

---

## 5. Сопоставление с текущими параметрами

| SKU | Старый коэф. | Текущий purchase_coeff | Старый min_stock | Текущий min_stock_kg |
|-----|------------:|----------------------:|-----------------:|---------------------:|
| RAW_001 | 1.0 | 1.0 | 17.61 | 17.61 |
| RAW_010 | **1.3** | 1.0 | 3,131.57 | 3,131.57 |
| RAW_011 | **1.3** | 1.0 | 2,256.76 | 2,256.76 |
| RAW_025 | 1.0 | 1.0 | 6,678.41 | 6,678.41 |

**min_stock_kg** — полностью совпадает (мigrated из purchase_plan_setting).

**purchase_coefficient** — для 73 SKU совпадает (=1.0). Для 2 SKU (RAW_010, RAW_011) текущее значение 1.0, хотя старое — 1.3.

---

## 6. Анализ min_stock_kg

| Показатель | Количество |
|------------|----------:|
| Заполнен (> 0) | 48 |
| = 0 | 11 |
| NULL | 16 |
| **Средний** (для заполненных) | **788 кг** |
| **Минимальный** | 0.02 (RAW_006) |
| **Максимальный** | 6,678 (RAW_025) |

---

## 7. Исторический контекст

Данные `purchase_plan_setting` были импортированы из Excel-каталога при начальной загрузке Supply. Ручной ввод (`manual_input = true`) был выполнен для всех 61 SKU. Среднемесячный расход (`manual_avg_usage`) составляет от 0.1 кг до 26,390 кг.

---

## 8. Вывод

| Факт | Значение |
|------|----------|
| Большинство коэффициентов | 1.0 |
| Только 2 SKU имеют коэффициент > 1 | RAW_010, RAW_011 (= 1.3) |
| min_stock_kg мигрирован полностью | 58/75 SKU |
| min_stock_kg = 0 | 11 SKU (нет запаса) |
| min_stock_kg = NULL | 16 SKU (нет данных) |
| Средний min_stock_kg | 788 кг |

### Ключевой вывод

Старая система КЛМ **фактически не использовала коэффициенты закупки** для большинства позиций. Только 2 из 75 SKU имели коэффициент > 1.0. Это подтверждает, что система работала в режиме «закупка = потребность + минимальный остаток» без дополнительных коэффициентов.

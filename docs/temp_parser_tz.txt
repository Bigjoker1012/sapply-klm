Кекс, при загрузке рецепта в PDF получаем 500.

На фронтенде:
POST /api/upload/recipe → 500 Internal Server Error.

Backend пытается выполнить:

/opt/supply-klm/pdf-venv/bin/python3 \
/opt/supply-klm/server/scripts/parse_recipe.py \
/tmp/klm_recipe_1790137566122.pdf

Команда завершается ошибкой.

Нужно НЕ менять фронтенд и НЕ маскировать 500.

1. Найди реальную причину падения parse_recipe.py.
2. Посмотри полный traceback в server logs.
3. Выполни команду вручную на сервере с этим PDF, чтобы получить traceback.
4. Проверь:
   - существует ли /tmp/klm_recipe_1790137566122.pdf;
   - читается ли PDF;
   - запускается ли /opt/supply-klm/pdf-venv/bin/python3;
   - установлены ли все зависимости parser'а именно в pdf-venv;
   - есть ли проблема с библиотекой PDF/OCR/таблицами;
   - не ожидает ли parser другой формат входного файла.
5. Проверь, почему parse_recipe.py запускается два раза.
6. После определения ROOT CAUSE исправь только необходимую часть.
7. Добавь нормальное логирование traceback на сервере.
8. В случае ошибки API должно возвращать понятный JSON:
   {
     "ok": false,
     "error": "...",
     "stage": "parse_recipe"
   }
   вместо безымянного 500.
